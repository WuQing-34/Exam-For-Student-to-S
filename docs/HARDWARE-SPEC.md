## 1. 服务器带宽容量分析（月流量 600GB）

### 1.1 前提假设

- 一台云服务器同时部署**考试系统**和**销售管理系统**两个 Node.js 应用
- **服务器规格**：2核4G / 70GB SSD / 6Mbps 带宽 / 600GB 月流量
- PM2 Cluster 模式，前端 SPA 由 Nginx 反代 + gzip 压缩
- 浏览器缓存命中率 95%（SPA JS/CSS 强缓存），剩余 5% 为首次访客或缓存失效

### 1.3 容量计算

```
月流量预算：600 GB
日流量预算：600 ÷ 30 = 20 GB/天
带宽上限：6 Mbps = 0.75 MB/s（瞬时峰值约束，非瓶颈）

安全余量：保留 30% 应对突发流量、系统更新、异常重试
实际可用：20 × 0.7 = 14 GB/天 = 14,336 MB/天
```

> 6Mbps 带宽绰绰有余——满负荷下日流量 14GB 折算平均速率仅 ~0.16 MB/s，远未触及带宽上限。即便全部考试集中在 4 小时内，峰值速率约 0.4 MB/s，仍有近一倍的带宽余量。

**日流量公式：**

```
可用流量 = 销售人数 × 销售日均流量 + 学生人数 × 学生日均流量

其中：
  学生日均流量 = 考试比例 × 考试日流量 + (1-考试比例) × 非考试日流量
```

**保守估值（含所有开销、重试、异常）：**

| 参数 | 保守值 | 说明 |
|------|------|------|
| 销售日均总流量 | 3 MB | 考试系统 0.8MB + 销售系统 1.2MB + 余量 |
| 学生考试日流量 | 1 MB | API 0.16MB + 前端 0.1MB + 浏览器开销 + 余量 |
| 学生非考试日流量 | 0.3 MB | 同上逻辑 |
| 日考试比例 | 30% | 约三分之一学生每天参加考试 |

**计算（按 1500 销售）：**

```
14,336 = 1500 × 3 + X × (0.3 × 1 + 0.7 × 0.3)
14,336 = 4,500 + X × 0.51
X = 9,836 ÷ 0.51
X ≈ 19,000
```

### 1.4 结论：600GB 月流量承载能力

| 场景 | 销售人数 | 学生人数 | 日考试量 | 月流量消耗 |
|------|:------:|:------:|:------:|:------:|
| 灰度阶段 | 50 | 500 | 150 场 | ~8 GB |
| 稳产阶段 | 1,500 | 5,000 | 1,500 场 | ~207 GB |
| 扩量阶段 | 1,500 | 10,000 | 3,000 场 | ~281 GB |
| **满负荷** | **1,500** | **~19,000** | **5,700 场** | **~416 GB** |
| 极限（取消余量） | 1,500 | ~29,000 | 8,700 场 | ~565 GB |

销售流量占比：1500 人 × 3MB × 30天 = 135 GB/月，占总流量的 22%（满负荷下），是固定开销。

> **关键结论**：一台 600GB 月流量服务器，同时运行考试系统和销售系统，**保守支撑 1500 销售 + 1.9 万学生**。如果使用 CDN 分担静态资源，还能再提升 30-50%。

## 2. 数据库容量分析

### 2.1 MySQL 各配置档位及承载能力

#### 单条记录大小估算

| 表 | 单条大小 | 增长速度 | 说明 |
|------|------:|------|------|
| student | ~200 B | 随学生数增长 | 含索引 |
| admin | ~200 B | 随销售增长 | 销售账号，按 1500 人 × 1.5 倍余量 |
| paper | ~2 KB | 慢增长 | 试卷不常增删 |
| question | ~800 B | 随试卷增长 | 每卷约 10-30 题 |

#### MySQL 配置推荐

| 配置 | CPU/内存 | 存储 | 最大连接数 | 简单 QPS | 推荐学生规模 | 年费 |
|------|---------|------|:------:|:------:|------|------:|
| **基础版（当前选购）** | 1核2G | 50G SSD | ~400 | ~800 | ≤ 15 万 | **¥98** |
| 高可用版 | 2核4G | 100G SSD | ~800 | ~2,000 | 15-50 万 | ~¥400 |
| 高可用版 | 4核8G | 200G SSD | ~1,600 | ~5,000 | 50-100 万 | ~¥800 |

**推荐方案：直接选购「基础版 1核2G」。**

理由：
- ¥98/年（≈¥8.2/月）价格极低，无需从 1核1G 过渡
- 你的业务全是简单 CRUD，无 JOIN 大表、无聚合查询
- 800 QPS 对应线上约 9,000 人同时考试（每人在 20 分钟内约 100 次 API 请求 = 0.083 QPS/人）
- 50GB 存储足够存 15 万学生的全量数据 + 一年内的考试记录

**何时需要升配：**

| 触发条件 | 升配到 |
|------|------|
| CPU 持续 > 60% | 1核2G |
| 连接数 > 200 | 检查连接泄漏，必要时升 2核4G |
| 慢查询 > 1 秒 | 先加索引，再升配 |
| 存储使用 > 70% | 扩容磁盘 或 升级档位 |

### 2.2 Redis 配置

#### 用量分析

考试系统 Redis 仅存学生 session：

| 项目 | 数据 |
|------|------|
| 单条 session 大小 | ~200 B（student_id + token + TTL 元数据） |
| TTL | 24 小时自动过期 |
| 峰值并发 session 数 | ≈ 当日活跃学生数 |
| 1 万活跃学生 | 1 万 × 200 B = **~2 MB** |
| 10 万活跃学生 | 10 万 × 200 B = **~20 MB** |

Redis 几乎不增长（TTL 自动清理）。

#### 配置推荐

| 配置 | 内存 | 最大连接数 | 推荐学生规模 | 年费 |
|------|:------:|:------:|------|------:|
| **标准版 256MB（当前选购）** | 256 MB | 10,000 | ≤ 50 万学生 | **¥78.8** |
| 标准版 1GB | 1 GB | 10,000 | 50 万+ | ~¥280 |

当前选购 Redis 版本：**Redis 7.0**。

> 256MB 版本承载 100 万并发 session 都绰绰有余（200 B × 100 万 = 200 MB）。
> 唯一需要升配的场景：未来 Redis 用于缓存题目/成绩等业务数据。

### 2.3 域名与 SSL 证书

#### 域名选购

考试系统和销售系统分开部署、分开访问，建议用**同一个主域名 + 两个子域名**：

| 用途 | 子域名示例 | 说明 |
|------|------|------|
| 考试系统（学生端） | `exam.example.com` | 学生注册、登录、答题 |
| 销售管理系统 | `crm.example.com` | 销售工作台、学员管理 |

只买一个主域名，通过 Nginx 按 `Host` 分发到两个应用，成本最低。

#### 域名价格（按后缀）

| 后缀 | 年费 | 适用场景 |
|------|------:|------|
| `.com` | **¥83** | 首选，国际通用性最强 |
| `.cn` | **¥33** | 国内备案方便，需实名认证 |
| `.com.cn` | **¥33** | 企业首选，备案最顺畅 |

> ⚠️ **续费建议**：企业账号续费比个人账号优惠幅度大，建议用**企业账号购买**以享受续费折扣。
> 业务正式运营推荐 `.com` 或 `.com.cn`，不推荐廉价后缀（`.top` / `.xyz` 等）。

#### SSL 证书

HTTPS 是刚需（用户登录、答题数据必须加密传输）：

| 方案 | 费用 | 有效期 | 说明 |
|------|------:|------|------|
| **Let's Encrypt** | **¥0** | 90 天 | 免费，certbot 自动续期，支持泛域名 |
| 腾讯云免费 SSL | ¥0 | 1 年 | 单域名，控制台一键申请 |
| 腾讯云付费 DV | ¥500-900/年 | 1-2 年 | 泛域名 + 保险赔付 |
| 腾讯云 OV/EV | ¥2,000-6,000/年 | 1-2 年 | 企业验证，地址栏绿色锁 |

> 推荐 **Let's Encrypt 泛域名证书**（免费 + 自动续期），或**腾讯云免费 SSL**（手动续期但省心）。灰度上线用免费的完全够。

#### Nginx 配置要点

```
# 泛域名证书一次覆盖所有子域名
server {
    server_name exam.example.com;
    listen 443 ssl;
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    location / { proxy_pass http://127.0.0.1:3001; }
}

server {
    server_name crm.example.com;
    listen 443 ssl;
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    location / { proxy_pass http://127.0.0.1:3002; }
}

# HTTP 全部跳转 HTTPS
server {
    listen 80;
    server_name exam.example.com crm.example.com;
    return 301 https://$host$request_uri;
}
```

## 5. 注意事项

1. **服务器、MySQL、Redis 必须同一地域同一 VPC**，否则数据库会产生公网流量费
2. MySQL 和 Redis **不要开公网访问**，仅通过内网 IP 连接
3. 两个系统可共用同一个 MySQL 实例，使用不同 database 隔离（`exam_system` / `sales_system`）
4. Redis 也共用同一实例，使用不同 `db` 编号（考试系统用 DB0，销售系统用 DB1）
5. 600GB 流量是**出站流量**，入站（用户上传数据）通常不计费
6. 如果未来前端静态资源成为瓶颈，加一个 CDN（腾讯云 CDN 国内流量约 ¥0.2/GB）
7. **国内服务器必须 ICP 备案**才能绑域名，备案期间用 IP + 端口做灰度测试
8. SSL 证书用 Let's Encrypt 免费泛域名，certbot 设置 crontab 自动续期（每月 1 号和 15 号）
9. **域名和云产品建议用企业账号购买**，续费价格明显低于个人账号
